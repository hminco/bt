# GA4 정의서

> ※ 구글 스크립트를 통해 작성되며 시트는 자동 업데이트됩니다.

- 프로젝트명: 닥터빌 주간 월간 ga데이터 자동 시트저장

## 1. 공통 기준

모든 탭에 공통으로 적용되는 필터입니다.

| 조건 | 내용 |
|---|---|
| 로그인 조건 | `사용자 ID로 로그인함 = Yes`인 트래픽만 집계 |
| 내부 트래픽 제외 | `테스트 데이터 필터 이름 = internal`인 트래픽 제외 |
| 대상 도메인 | 호스트명에 `m.doc` 또는 `www` 포함. 닥터빌 모바일과 닥터빌 PC를 세그먼트 구분 없이 합산 |
| 페이지별 리포트 기기 조건 | **PC만** 집계. 모바일 페이지별 리포트는 별도 구축하지 않음 |
| 전체/주간/월간 리포트 기기 조건 | 전체(기기 구분 없음), PC, MO(PC 제외) 세 가지로 각각 집계 |

## 2. 기간 정의

| 구분 | 정의 |
|---|---|
| **주(週)** | 월요일~일요일 7일. 예: `2026-06-01`은 6/1(월)~6/7(일) |
| **월(月)** | 달력월 1일~말일. 예: `2026-06`은 6/1~6/30 |
| **집계 시점** | 항상 가장 최근에 완료된 기간만 집계. 스크립트 실행 시점이 해당 주 또는 월의 중간이면 집계하지 않고 그 이전에 완료된 기간까지만 채움 |
| **백필(과거 데이터 채우기)** | `backfillFromJune` 실행 시 2026년 6월 1일(월)부터 현재까지 완료된 모든 주와 월을 순차적으로 채움 |

## 3. 핵심 지표 정의

### GA4 API 수집 데이터 안내

GA4 API로 자동 수집한 데이터입니다. GA4는 자체적으로 샘플링과 모델링을 적용하고, API의 "필터" 방식과 GA4 화면의 "세그먼트" 방식은 사용자 계산 시 미묘한 차이가 있어 완전한 오차 제로는 어렵습니다.

활성사용자와 조회수 등 핵심 지표는 0.1~0.3% 이내로 거의 일치합니다. 신규사용자와 재방문자는 계산 방식 차이로 2~4% 수준의 오차가 있을 수 있으나 실무상 신뢰 가능한 수준입니다.

### 데이터 업데이트

- **평소**: 트리거가 설정되어 있으면 매주 월요일과 매월 1일에 최신 데이터가 자동으로 입력됩니다. 별도로 작업할 필요가 없습니다.
- **트리거를 놓쳤거나 최신 데이터가 급하게 필요한 경우**: `weeklyGA4Sync`, `monthlyGA4Sync`, `pageWeeklyGA4Sync`, `pageMonthlyGA4Sync` 네 개를 실행합니다. 가장 최근에 완료된 한 개 기간만 빠르게 채웁니다.
- **여러 기간이 한꺼번에 빠진 경우**: `backfillFromJune`을 실행합니다. 6월부터 현재까지 빠진 기간을 모두 채우며, 이미 존재하는 기간은 건너뛰므로 여러 번 실행해도 안전합니다.

### DAU / WAU / MAU

기간에 따라 계산 방식이 다르므로 반드시 확인합니다.

| 리포트 | DAU | WAU | MAU |
|---|---|---|---|
| **주간 리포트** | 해당 주(월~일) 7일간의 일별 활성사용자수 평균 | 해당 주(월~일) 7일 전체의 활성사용자수 | 주 종료일인 일요일 기준 GA4의 28일 롤링 활성사용자. 해당 시점 기준 최근 28일 |
| **월간 리포트** | 해당 달 전체 일수의 일별 활성사용자수 평균 | 해당 달에 포함된 각 주(`yearWeek` 기준)의 활성사용자수 평균 | 해당 달 전체의 활성사용자수. `활성사용자` 컬럼과 동일한 값 |

> ⚠️ 주간 리포트의 MAU와 월간 리포트의 MAU는 서로 다른 방식으로 계산됩니다. 주간 MAU인 28일 롤링 값과 월간 MAU인 달력월 전체 값을 직접 비교하지 않습니다.

### 기타 지표

| 지표 | 정의 |
|---|---|
| 조회수 | `screenPageViews` 합계 |
| 일별평균조회수(월~금) | 해당 주의 **월~금 5일만** 조회수 합계 ÷ 5. 주간 리포트 전용 |
| 사용자당조회수 / 활성사용자당조회수 | 조회수 ÷ 활성사용자 또는 WAU |
| 평균세션시간 | GA4 `averageSessionDuration`. 초 단위 |
| 신규사용자 / 재방문자 | 신규사용자는 GA4 `newUsers`, 재방문자는 `활성사용자 - 신규사용자`. 근사치이며 월간 리포트 전용 |
| 세션당평균참여시간 | `userEngagementDuration ÷ sessions`. 월간 리포트 전용 |
| 활성사용자당참여세션수 | `engagedSessions ÷ activeUsers`. 월간 리포트 전용 |
| 세션당조회수 | `조회수 ÷ sessions`. 월간 리포트 전용 |
| DAU/WAU(%), DAU/MAU(%), WAU/MAU(%) | 스티커니스(재방문 빈도) 지표. 높을수록 사용자가 자주 재방문한다는 의미 |
| **평균참여시간(페이지별, 근사치)** | `userEngagementDuration ÷ screenPageViews`. 페이지 단위 실측이 아닌 근사 추정값 |
| **이탈률(%, 페이지별, 근사치)** | GA4 `bounceRate`를 해당 페이지가 포함된 세션 기준으로 산출. 엄밀히는 그 페이지가 랜딩 페이지인 세션의 이탈률과 다를 수 있음 |
| 조회수비중(%) / 활성사용자비중(%) | 그 페이지의 조회수 또는 활성사용자 ÷ 같은 기간 PC 전체 조회수 또는 활성사용자 × 100 |

## 4. 인사이트 판정 기준

| 판정 | 기준 |
|---|---|
| 개선/성장 | 증감률이 좋은 방향으로 ±5% 이상 변화 |
| 주의 필요 | 증감률이 나쁜 방향으로 ±5% 이상 변화 |
| 안정적 | 증감률이 ±5% 미만 |
| 이탈률 | 방향을 반대로 해석. 하락은 개선, 상승은 주의. 나머지 지표는 상승을 개선으로 판단 |
| 3주/3개월 연속상승·하락 | 최근 세 개 기간 동안 해당 지표가 한 번도 꺾이지 않고 계속 오르거나 내린 경우 |

## 5. 탭별 상세 설명

### 🔴 인사이트

- **역할**: 모든 증감, 추세, 서술형 요약을 시간순으로 누적 기록하는 로그
- **갱신 시점**: 주간, 월간, 페이지별 동기화 함수가 새 데이터를 추가할 때마다 자동 실행
- **구성**: WoW(전주 대비), MoM(전월 대비) 지표 증감, 기기 비중, 서술형 요약, 페이지별 급상승·급하락 TOP3, 3주·3개월 연속 추세

### 🟡 월간요약 / 주간요약

- **역할**: 전체, PC, MO 지표를 기존 주간지표·월간지표와 같은 구조인 `1행 = 1기간 + 1기기`로 보여주며, 각 행 끝에 전 기간 대비 인사이트 텍스트를 표시
- **구분선**: 기간이 바뀔 때마다 3행 단위로 얇은 선을 표시
- **비교 기준**: 같은 기기끼리 직전 기간과 비교. 전체는 전체, PC는 PC, MO는 MO와 비교

### 🟡 월간페이지요약 / 주간페이지요약

- **역할**: 페이지별 지표를 `기간 × 페이지 그룹` 단위로 한 행씩 나열하고 인사이트 텍스트를 표시
- **구분선**: 기간이 바뀔 때마다 32행 단위로 얇은 선을 표시
- **비교 지표**: 조회수, 활성사용자, 평균참여시간, 이탈률 네 개 중 가장 우려되는 지표 한 개와 가장 긍정적인 지표 한 개만 표시

### 🔵 주간지표 / 월간지표

- **역할**: 전체, PC, MO 원본 데이터를 모든 산출 지표와 함께 전 기간에 이어 누적 저장
- **구분선**: 기간이 바뀔 때마다 3행 단위로 얇은 선을 표시
- **용도**: 요약 탭, 추이 탭, 인사이트가 모두 이 원본 데이터를 참조해 계산

### 🟢 전체지표_추이_주간 / 전체지표_추이_월간

- **역할**: 최근 3주 또는 최근 3개월만 추출해 전체, PC, MO를 표와 차트로 시각화
- **차트**: 조회수 추이, DAU/MAU 스티커니스 추이
- **갱신 방식**: 누적하지 않고 매번 완전히 새로 생성해 항상 최신 세 개 기간만 표시

### 🟣 페이지별지표_주간 / 페이지별지표_월간

- **역할**: 32개 페이지 그룹별 원본 데이터를 PC 기준으로 누적 저장
- **구분선**: 기간이 바뀔 때마다 32행 단위로 얇은 선을 표시

### 🟣 페이지별추이_주간 / 페이지별추이_월간

- **역할**: 최근 3주 또는 최근 3개월만 추출해 32개 페이지를 표와 차트로 시각화
- **차트**: 조회수 상위 8개 추이, 이탈률 상위 8개 추이, 조회수 비중 상위 8개 추이
- **갱신 방식**: 매번 완전히 새로 생성

## 7. 실행 함수 목록

| 함수명 | 용도 |
|---|---|
| `weeklyGA4Sync` | 가장 최근에 완료된 주 한 개만 동기화. 매주 실행용 |
| `monthlyGA4Sync` | 가장 최근에 완료된 달 한 개만 동기화. 매월 실행용 |
| `pageWeeklyGA4Sync` / `pageMonthlyGA4Sync` | 페이지별 버전 |
| `backfillWeeklyGA4(fromMondayStr)` / `backfillMonthlyGA4(fromYear, fromMonth)` | 과거 특정 시점부터 현재까지 모두 채움 |
| `backfillPageWeeklyGA4` / `backfillPageMonthlyGA4` | 페이지별 버전 |
| `backfillFromJune` | 위 네 개 백필 함수를 2026년 6월 기준으로 한 번에 실행 |
| `generateInsights` | 인사이트, 요약, 전체지표 추이 탭을 기존 데이터로부터 재구성. API 호출 없음 |
| `generatePageInsights` | 페이지 인사이트, 페이지 요약, 페이지 추이 탭을 재구성. API 호출 없음 |

## 8. 알려진 한계

- 페이지별 리포트는 **PC만** 집계하며 모바일 페이지별 리포트는 별도로 구축하지 않습니다.
- 이탈률과 페이지별 평균참여시간은 근사치이며 GA4 UI의 정밀한 페이지 단위 지표와 정확히 일치하지 않을 수 있습니다.
- 월간 WAU 계산 시 해당 달의 첫 주와 마지막 주가 다른 달과 겹쳐 7일 미만으로 집계될 수 있습니다.
- 신규사용자와 재방문자 비교 시 GA4 탐색(Exploration) 화면의 세그먼트 방식과 API 필터 방식 사이에 0.1~2% 수준의 미세한 오차가 있을 수 있습니다. 실무상 무시 가능한 범위입니다.
